# Документация

- Если пользователь просит написать скрипт, прочитай инструкции из `docs/scripts_info.md`
- Если в запросе пользователя есть «файл индекса», «индекс» или «INDEX.md», прочитай инструкции из `docs/index_files.md`

# Стиль кода

- Весь проект ведётся на русском языке, включая `README.md`, документацию, строки документации (docstring), комментарии и `AGENTS.md`.
- Все импорты модулей должны быть без `src.` в пути, поскольку используется `PYTHONPATH=src`.
- Для каждого класса, метода и функции добавляй однострочную строку документации с описанием назначения, без описания аргументов и возвращаемых значений.
- По умолчанию добавляй аннотации типов ко всем методам и функциям.
- Для моделей данных всегда используй Pydantic; не используй dataclasses. Если класс описывает какие-то данные, то старайся класть в модуль в файл `resources.py`.
- Файлы `__init__.py` предназначены только для импортов; размещай логику в отдельных модулях.
- После внесения изменений запускай `make check` для проверки линтерами и запуска тестов.
- Не используй `frozenset`; везде используй обычный `set`.

# Файлы

- Все проекты с расширениями из `CATEGORY_EXTENSIONS["logic"]` (сейчас `.logicx` и `.band`) всегда считай файлами, даже если физически это каталоги. Не дублируй список расширений в проверках. Перемещай проект целиком, без обхода или объединения его содержимого. Используй общие проверки из `src/core/logicx.py`.
- Для разрешения конфликтов имён используй `numbered_path` из `src/core/duplicates.py`.
