# Сортировка ресурсов индекса

Скрипт `src/scripts/tidy_up_index.py` перемещает поддерживаемые файлы из корня
музыкальных директорий в подпапки. Музыкальная директория определяется обычным
файлом `INDEX.md` непосредственно внутри неё.

## Настройка и запуск

Задайте `INDEX_DIR` в `src/scripts/__init__.py`. По умолчанию используется
`/Users/deniskrumko/Yandex.Disk.localized/Музыка/Index`.
Относительный путь отсчитывается от текущей рабочей папки, `~` раскрывается.
В `EXCLUDE_DIRS` перечислите пути папок, которые нужно пропускать целиком
вместе со всем содержимым. По умолчанию исключена `INDEX_DIR / "_НАЙТИ"`.
Относительные пути исключений также отсчитываются от рабочей папки; `~` раскрывается.

```sh
PYTHONPATH=src uv run src/scripts/tidy_up_index.py
```

Для предварительного просмотра добавьте `--dry-run`:

```sh
PYTHONPATH=src uv run src/scripts/tidy_up_index.py --dry-run
```

В этом режиме скрипт выводит исходные и целевые пути, включая номерные суффиксы
при совпадениях, а также план удаления пустых подпапок. Изменений на диске нет.
Имена, занятые предыдущими пунктами плана, также учитываются.
Итоговые списки показывают текущее состояние диска, до перемещений.

Поиск рекурсивный, но после обнаружения музыкальной директории спуск в неё
прекращается. Сам `INDEX_DIR` тоже может быть музыкальной директорией.
Символические ссылки и внутренности проектов категории `logic` не обходятся.

## Раскладка

Перед раскладкой скрипт рекурсивно удаляет подпапки музыкальных директорий,
в которых нет файлов по проверке `core.logicx.is_file`. Это включает пустые
категории и папки только с `.DS_Store`, скрытыми бэкапами Guitar Pro или ссылками.
Пустые вложения удаляются и внутри папок с ресурсами. Сама музыкальная директория
и подпапки с `INDEX.md` сохраняются. Проекты категории `logic` считаются файлами
даже при пустом содержимом; их внутренности не обходятся. Каждое удаление выводится
в консоль. Ссылки не обходятся, их целевые файлы остаются на месте.

Соответствие подпапок и расширений задаётся только в `CATEGORY_EXTENSIONS`
в [src/core/file_extensions.py](../../src/core/file_extensions.py).
Этот словарь используют сортировка, crawler и `MusicDir`.
Регистр расширений не учитывается.

Проекты из категории `logic` всегда считаются файлами, даже если физически
это директории: каждый проект перемещается целиком. Непустые директории,
симлинки, `INDEX.md` и неподдерживаемые файлы остаются на месте.
Файлы внутри существующих подпапок не сортируются.

Категория создаётся только при необходимости. При совпадении имён выбирается
первое свободное имя: `file (2).mp3`, `file (3).mp3` и так далее. Существующие
файлы, директории и даже оборванные ссылки считаются занятыми именами.
Общая функция `core.duplicates.numbered_path` используется также в crawler.

Если путь нужной категории занят файлом или симлинком, выполнение останавливается
с ошибкой. Завершённые перемещения сохраняются; следующий запуск продолжает работу.
После успешной сортировки повторный запуск ничего не перемещает.
Скрипт выводит каждый перенос и общее число перенесённых файлов, включая проекты.
Коды завершения: `0` — успех, `1` — ошибка, `130` — отмена пользователем.

## API ресурсов

```python
from pathlib import Path

from index.utils import get_music_dirs
from music_dir import MusicDir

for path in get_music_dirs(Path("/music/Index")):
    music = MusicDir(path=path)
    recordings = music.dict_files
    mixes = music.bounce_files
    projects = music.logic_files
    tabs = music.tab_files
    images = music.image_files
    folders = music.subdirs
    remaining = music.other_files
```

`MusicDir` — Pydantic-модель. Каждое свойство возвращает актуальный отсортированный
список `Path`, читая состояние диска при обращении:

- `dict_files`, `bounce_files`, `logic_files`, `tab_files`, `image_files` — только соответствующие
  форматы непосредственно в своей подпапке; отсутствующая категория даёт `[]`.
- `subdirs` — обычные подпапки корня, кроме категорий и проектов категории `logic`.
- `other_files` — файлы корня, включая проекты категории `logic`, кроме `INDEX.md`, `.DS_Store` и бэкапов Guitar Pro `.<name>.bak`.

Симлинки исключены из всех списков. Рекурсивного чтения ресурсов нет.
Проверки `core.logicx.is_file`, `is_directory`, `is_logicx` обеспечивают общее
правило работы с пакетами Logic Pro.

## Итоговые списки для проверки

После сортировки и общего числа переносов скрипт выводит три списка путей:

- Папки с `other_files` — в корне остались файлы кроме `INDEX.md`.
- Папки с `subdirs` — есть подпапки вне категорий ресурсов.
- Папки без файлов кроме индекса — нет файлов ни в корне, ни во вложениях.
  Пустые подпапки не считаются файлами, а проекты категории `logic` считаются файлами
  даже при пустом содержимом. Симлинки, файлы `INDEX.md`, `.DS_Store` и бэкапы Guitar Pro `.<name>.bak` не учитываются.

Одна папка может попасть в несколько списков. Для пустого списка выводится «нет».
Папки из `EXCLUDE_DIRS` и их содержимое в отчёт не попадают.

Расширения проектов берутся из `CATEGORY_EXTENSIONS["logic"]`: каждый такой
проект считается цельным файлом, не обходится и не объединяется с другим проектом.
Это правило также действует при валидации, сортировке и проверке пустых папок.
