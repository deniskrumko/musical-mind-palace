# Web плеер музыки

Код расположен в src/web_player/

## Поиск музыки

- музыка берется из индекс директории `INDEX_DIR`
- в ней ищутся все существующие `MusicDir`
- в каждой музыкальной директории берутся все музыкальные файлы через property `all_music_files`
- формируется итоговый большой список всех найденных музыкальных файлов (пути к ним)
- Список собирается один раз при запуске сервера. Для обновления библиотеки сервер
  нужно перезапустить.
- Порядок по умолчанию: директории в порядке `get_music_dirs`, внутри каждой —
  файлы в порядке `all_music_files` (сначала `dict_files`, затем `bounce_files`).
- Пустая библиотека отображается сообщением; кнопки воспроизведения отключены.
- Статистика плеера показывает общее число найденных музыкальных директорий
  (включая директории без аудио) и музыкальных файлов из `all_music_files`.
  Эти значения сохраняются при переходах, пропуске директорий и перемешивании.

## Веб плеер

- Плеер запускается как FastAPI приложение (на старте можно указать хост и порт, по умолчанию порт 8090)
- Для отрисовки используется Jinja2 как отрисовка шаблонов
- Код UI написан на Vanilla JS
- Вся статика лежит в src/web_player/static/, в под-директориях js, css, templates
- Плеер адаптирован для компьютеров и телефонов.
- Плеер умеет воспроизводить найденные файлы, умеет перелистывать их вперед-назад, имеет скролл-бар для пролистывания трека
- По песне выводится: название файла, название директории (относительно `INDEX_DIR`), продолжительность
- На компьютере (ширина окна от 768 px) кнопка «Открыть» открывает папку текущего
  аудиофайла в Finder и выделяет его. Используется файл, загруженный в этом браузере,
  даже если с другого устройства уже переключили общую очередь. На телефоне кнопка
  скрыта, при пустой библиотеке отключена. Воспроизведение продолжается.
  Finder открывается на Mac, где запущен сервер плеера; при подключении с другого
  компьютера папка откроется на сервере. Требуется macOS; ошибка открытия показана в плеере.

## Плейлист

- Плейлист — единая последовательность песен без секций «Уже звучало», «Сейчас»,
  «Далее», без нумерации и без объединения файлов по директориям.
  У каждой песни сверху отображается имя файла, снизу — её директория мелким
  приглушённым текстом, как подпись исполнителя. Директория повторяется у каждого
  файла. Длинные подписи сокращаются многоточием; полные имена доступны
  во всплывающей подсказке.
- Треки кликабельны: нажатие выбирает файл в общей очереди и запускает воспроизведение,
  в том числе после shuffle. Нажатие на текущий файл продолжает воспроизведение.
  Мобильное окно плейлиста остаётся открытым.
- При переходах меняется подсветка текущего трека; уже загруженные строки остаются
  на своих местах: переход вперёд или назад не удаляет строки и не переносит их
  между секциями. Все прослушанные файлы доступны выше текущего без ограничения
  в 10 треков. Пропущенные файлы тоже остаются в ленте и доступны для выбора.
- Сначала загружаются первые 100 файлов. При прокрутке к нижнему краю добавляются
  следующие 100 к уже загруженным, пока список не будет загружен целиком.
  Во время прослушивания, если текущая песня оказывается дальше загруженной части,
  необходимые порции догружаются автоматически. Лимит 100 задаёт размер порции,
  а не максимальное число отображаемых файлов.
- На компьютере переключение вперёд, назад или выбор песни прокручивает панель
  к текущей строке, включая автоматический переход после окончания трека.
  Прокручивается только плейлист, а не страница целиком.
  На телефоне каждое открытие плейлиста показывает текущую песню независимо
  от того, где пользователь остановил прокрутку при предыдущем открытии.
- После shuffle сохраняется прослушанная часть и текущая песня, будущие файлы
  отображаются в новом порядке; страницы плейлиста загружаются заново.
- Ошибка подгрузки показывается внутри плейлиста с кнопкой «Загрузить ещё»
  для повторной попытки; воспроизведение продолжается.

## Плейлист на компьютере и телефоне

- На компьютере (ширина окна от 768 px) плеер и плейлист расположены в две колонки.
  Плейлист всегда виден справа; кнопок открытия и закрытия нет.
  Длинная очередь прокручивается внутри боковой панели.
- На телефоне (ширина окна до 767 px включительно) виден плеер с короткой кнопкой
  «Список». Плейлист по умолчанию закрыт.
- «Список» открывает модальное окно у нижнего края экрана с затемнением фона.
  Высота окна — до 90% экрана; длинная очередь прокручивается внутри него.
  Фон недоступен для нажатий, прокрутка страницы блокируется до закрытия окна.
- Закрыть мобильный плейлист можно кнопкой «Закрыть», нажатием на затемнённый фон
  или Escape. Открытие и закрытие не прерывают воспроизведение и не меняют очередь.
- При увеличении ширины до 768 px модальное окно становится постоянно видимой
  боковой панелью. При уменьшении ширины до мобильной плейлист закрывается
  и снова доступен по кнопке «Список».

## Очередь и воспроизведение

- Приложение рассчитано на одного пользователя. Очередь и текущий трек едины
  для всех устройств и хранятся в памяти единственного процесса сервера.
- После завершения трека автоматически включается следующий. После последнего
  воспроизведение останавливается; зацикливания нет.
- В обычном режиме сначала последовательно воспроизводятся файлы текущей
  музыкальной директории, затем файлы следующей директории.
- Кнопка «Следующая директория» пропускает оставшиеся файлы текущей музыкальной
  директории и выбирает первый файл следующей. При воспроизведении звук продолжается,
  при паузе новый файл остаётся на паузе. В последней директории кнопка отключена.
- Пропущенные кнопкой файлы исключаются из будущего автоматического воспроизведения
  и не добавляются в историю, но остаются видны и кликабельны в плейлисте.
  «Предыдущий трек» после такого перехода возвращает к файлу, который звучал перед ним.
- Кнопка Shuffle («Перемешать») отправляет запрос серверу и случайно перемешивает
  только оставшиеся треки. Текущий трек, позиция воспроизведения и история сохраняются.
- После shuffle очередь состоит из отдельных файлов без группировки по директориям.
  Кнопка «Следующая директория» скрыта, серверный переход по директориям отключён.
  Режим сохраняется до перезапуска сервера, даже если случайно выпал исходный порядок.
- Кнопка «назад» возвращает предыдущий трек из истории, а покинутый трек становится
  следующим в очереди. Прослушанные файлы сохраняются в ленте без ограничения количества.
- Браузер сохраняет идентификатор текущего трека и время воспроизведения в
  `localStorage`. После обновления страницы позиция восстанавливается, если
  сохранённый трек совпадает с текущим на сервере. Запуск звука — по нажатию Play.
- При открытии с другого устройства показывается текущий трек серверной очереди.
  Позиция локальна для браузера, синхронизации звучания между устройствами нет.
- После перезапуска сервера очередь возвращается к исходному порядку и первому треку.
- Продолжительность текущего трека определяется браузером после загрузки метаданных.
  В списке очереди показываются имена файлов и музыкальных директорий без длительности.
- Директория трека — путь `MusicDir.path` относительно `INDEX_DIR`, без `dict`/`bounce`.
- Если файл удалён или браузер не поддерживает его кодек, показывается сообщение,
  затем включается следующий трек. Если следующих треков нет, плеер останавливается.
- Аудио отдаётся с поддержкой HTTP Range для перемотки. Конвертации файлов нет.

## Управление с экрана блокировки

- При поддержке браузером [Media Session API](https://developer.mozilla.org/en-US/docs/Web/API/Media_Session_API)
  системный плеер, в том числе экран блокировки Safari на iPhone, получает
  название файла, музыкальную директорию, состояние воспроизведения и позицию.
- Play/Pause управляют текущим аудио, «Предыдущий трек» и «Следующий трек»
  вызывают те же серверные переходы между файлами, что и кнопки на странице.
  Они работают и после shuffle. Переход по директориям доступен только на странице.
- Действия `previoustrack` и `nexttrack` зарегистрированы явно; действия перемотки
  `seekbackward`/`seekforward` отключены, чтобы системный плеер использовал переключение
  файлов вместо кнопок ±10 секунд. Перемотка ползунком доступна на странице и через
  системное действие `seekto`, если браузер его поддерживает.
- Доступные системные элементы определяются браузером и версией iOS.
  Без Media Session API кнопки на странице продолжают работать.

## Запуск веб плеера

- Для запуска на хосте 0.0.0.0 и с портом по умолчанию - вызывайте команду `make local_webplayer`
- Для запуска на хосте с текущим IP (из ifconfig) и с портом по умолчанию - вызывайте команду `make webplayer`, текущий IP хоста определяется автоматически и запускается на нем, чтобы можно было из одного WiFi подключиться с телефона и послушать

Активный интерфейс определяется через `route -n get default`, его IPv4 — через
`ifconfig`. На телефоне откройте `http://<IP компьютера>:8090` в той же WiFi-сети.

Произвольные адрес, порт и библиотека:

```bash
PYTHONPATH=src uv run src/scripts/run_web_player.py --host 127.0.0.1 --port 8091 --index-dir /путь/к/INDEX
```

Подробности запуска: [run_web_player](scripts/run_web_player.md).

## HTTP API

- `GET /` — страница плеера.
- `GET /api/state` — текущий трек, история переходов и первые 100 будущих файлов,
  общее число файлов `total`, число найденных директорий `total_directories`,
  доступность переходов, `shuffled` и `has_next_directory`, индекс текущего файла
  `current_index`, длина ленты `playlist_total` и версия её порядка `playlist_revision`.
- `GET /api/playlist?offset=0` — до 100 строк единого плейлиста с указанного
  смещения, общее число файлов и версия порядка. Смещение не может быть отрицательным.
- `POST /api/next`, `POST /api/previous` — переходы общей очереди.
- `POST /api/next-directory` — переход к следующей музыкальной директории;
  после shuffle или в последней директории возвращает состояние без изменений.
- `POST /api/shuffle` — перемешивание будущих треков.
- `POST /api/select/{track_id}` — выбор текущего, будущего или ранее прослушанного
  файла, включая ранее пропущенные; неизвестный файл возвращает 404.
- `GET /audio/{track_id}` — аудиофайл по идентификатору из библиотеки.
- `POST /api/reveal/{track_id}` — показать известный аудиофайл в Finder на сервере
  macOS (204); неизвестный, удалённый или находящийся за пределами библиотеки файл
  возвращает 404, другая ОС — 501, ошибка запуска Finder — 500.
- `/static/` — JS, CSS и шаблоны в `src/web_player/static/`.
