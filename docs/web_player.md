# Веб-плеер

## Библиотека

- Состав библиотеки фиксируется при запуске. Чтобы увидеть новые или удалённые файлы,
  перезапустите сервер.
- Для трека доступны имя файла, путь музыкальной директории относительно `INDEX_DIR`,
  описание и теги из индекса, а также числа файлов по категориям.
- `Lyrics` отображается отдельной секцией «Текст песни» с сохранением переносов строк.
  `Rating` отображается в заголовке трека десятью звёздами и числом вида `7/10`.
  Оба поля исключены из обычного списка тегов; без значения их отображение скрыто.

## Очередь и управление

- Каждый браузер хранит свою очередь и текущий трек. Сервер предоставляет библиотеку,
  поиск и аудио; команды плеера не меняют воспроизведение на других устройствах.
  Открытые вкладки работают независимо и не синхронизируются в реальном времени.
- Плейлист и кнопки переходов используют текущую выдачу. Если выбранный трек не
  входит в неё, он продолжает играть до конца; кнопки переходов недоступны, а
  следующий трек нужно выбрать вручную. В конце списка воспроизведение останавливается.
- Переходы по директориям работают в пределах выдачи. Перемешивание случайно меняет
  порядок треков выдачи, помещая текущий трек первым, а остальные после него; переходы по директориям
  при этом скрыты. «Сброс» очищает поиск, фильтры и перемешивание без остановки звука.
- Трек, фильтры и перемешанная очередь сохраняются в браузере. После обновления
  страницы позиция воспроизведения восстанавливается для того же файла, звук
  автоматически не запускается. URL содержит текущий трек и фильтры, но не
  перемешанный порядок. Номер трека в URL десятичный, начинается с нуля и
  соответствует порядку библиотеки текущего запуска; после перезапуска он может
  указывать на другой трек. Для неизвестного номера показывается ошибка. При совпадении
  параметров ссылки с локальными фильтрами восстанавливается локальный порядок.
- Если аудиофайл удалён или браузер не поддерживает его формат, плеер показывает
  ошибку и не переключает трек. Перемотка работает через HTTP Range без конвертации.
  Подробности ошибки аудио (в том числе код и сообщение браузера) выводятся в
  консоль разработчика браузера; не найденные или недоступные файлы записываются
  в журнал сервера. Ответ аудиозапроса можно проверить на вкладке Network.

## Редактирование описания и тегов

- Кнопка с карандашом справа над описанием открывает редактор. Обычные секции
  скрываются, а сверху появляются кнопки «Сохранить» и «Отменить».
- Поле «Имя файла» меняет имя только текущего аудиофайла без расширения;
  расширение показано рядом и недоступно для редактирования. Переименование
  применяется общей кнопкой «Сохранить» только при изменении имени.
  «Отменить» отбрасывает новое имя вместе с остальными правками.
- При переименовании сохраняются звук, позиция, пауза, история и порядок очереди.
  Новое имя сразу появляется в заголовке и плейлисте. ID и аудиоадрес трека
  остаются прежними до перезапуска сервера; после перезапуска библиотека
  сортируется по актуальным именам файлов.
- Занятое имя, внешнее удаление, переименование или изменение аудиофайла приводят
  к ошибке без сохранения правок. Если запись индекса не удалась после
  переименования, исходное имя восстанавливается. Существующие файлы
  не перезаписываются, автоматический подбор имени с номером не выполняется.
- Поля строятся по `config/tags.toml` в порядке конфигурации с подписями
  `display_name`: строка, многострочный текст, список отдельных строк с кнопками
  добавления и удаления, кнопки одиночного или множественного выбора, селектор
  альбомов с именами из `config/albums.toml` и десять
  кликабельных звёзд оценки; логический тег редактируется кнопками «Да», «Нет» и
  «Не указано». Кнопка очистки логического тега выбирает «Не указано»; значения
  в `INDEX.md` — `true` или `false`. У каждого поля есть кнопка очистки.
- Тег `Album` хранит в `INDEX.md` список стабильных ID альбомов. В плеере и редакторе
  отображаются имена с годом в скобках; если год не задан, показывается `TBA`.
  При редактировании порядок выбранных альбомов сохраняется.
- Описание редактируется целиком как текст, включая Markdown-заголовок и ссылки.
  Очистка поля удаляет тег; пустое описание тоже допустимо. Заголовки `##`
  зарезервированы для тегов, внутри текста используйте `###`.
- Сохранение заменяет общий `INDEX.md` музыкальной директории и обновляет сведения
  всех её треков в памяти сервера без перезапуска и прерывания звука.
- Во время редактирования недоступны переключение треков и перемешивание, включая
  плейлист и команды с экрана блокировки. Пауза, Play и перемотка работают.
  Если трек закончился, следующий автоматически не запускается даже после
  сохранения или отмены: Play повторяет текущий трек с начала, также можно выбрать
  другой трек вручную.
- Если индекс изменился на диске после открытия формы, сохранение отклоняется
  с ошибкой, а форма и введённые значения остаются открытыми. Ошибки записи
  также сохраняют черновик. «Отменить» сразу отбрасывает правки; закрытие или
  перезагрузка страницы с правками вызывает предупреждение браузера.

## Запуск

- `make local_webplayer` запускает плеер на `0.0.0.0:8090`.
- `make webplayer` запускает его на автоматически определённом IP компьютера,
  чтобы подключиться к нему с телефона в той же Wi-Fi сети.
- Для произвольных параметров используйте `src/scripts/run_web_player.py`:

  ```bash
  PYTHONPATH=src uv run src/scripts/run_web_player.py --host 127.0.0.1 --port 8091 --index-dir /путь/к/INDEX
  ```

## Для разработки

- Реализация находится в `src/web_player/`: FastAPI, шаблон Jinja2 и Vanilla JS.
  Статика — в `src/web_player/static/`.
- Интерфейс использует `GET /api/library` для списка ID,
  `POST /api/library/search` для всех ID и директорий выдачи,
  `POST /api/library/tracks` для сведений порциями до 100 файлов,
  `GET /audio/{track_id}` и `POST /api/reveal/{track_id}`. Порядок и переходы
  поддерживаются браузером. Прежние маршруты очереди сохранены для совместимости
  и не используются интерфейсом.
- `GET /api/metadata/{track_id}` возвращает `track_id`, имя без расширения
  `filename`, расширение `extension`, версию аудиофайла `file_revision`, описание,
  значения тегов, конфигурацию полей и версию исходных байтов индекса `revision`.
  `PUT /api/metadata/{track_id}` принимает `filename`, `description`, `tags`
  и исходные `revision`, `file_revision`; проверяет значения через модуль `index`
  и сохраняет общее изменение имени и индекса. Индекс заменяется через временный
  файл в той же директории. При конфликте версии или занятом имени возвращается
  HTTP 409. Аудиофайл проверяется по имени, устройству, inode, размеру и времени
  изменения без чтения аудио целиком.
- Порядок библиотеки определяется при запуске сервера; сохранённая очередь
  восстанавливается, если её треки присутствуют в библиотеке.

## Фильтрация плейлиста

- Кнопка «Фильтры» открывает поиск по названию и значениям тегов с
  `use_in_text_search = true`, а также выбор значений тегов, для которых
  `use_in_filters` не отключён в конфигурации. По умолчанию теги в текстовый
  поиск не включены.
  Поиск проверяет имя последней директории и имена всех её треков; совпадение
  возвращает все треки этой музыкальной директории. Регистр и пробелы по краям
  запроса не учитываются. Значения одного тега объединяются
  через «ИЛИ», разные теги и строка поиска — через «И». Вариант «Не указано»
  соответствует отсутствующему тегу. Для свободных полей предлагаются значения
  из библиотеки; многострочные значения выбираются целиком. Сохранённые условия
  для отключённых или удалённых тегов не влияют на результаты. Оценки показаны
  одной шкалой из десяти звёзд; можно выбрать оценку и вариант «Не указано».
- «Найти» применяет условия, «Сбросить» возвращает полный список. Условия
  сохраняются в браузере и определяют локальный порядок воспроизведения.
  Применённые условия видны в виде чипсов; нажатие на чипс сразу удаляет
  соответствующее условие. После сохранения метаданных результаты обновляются.
