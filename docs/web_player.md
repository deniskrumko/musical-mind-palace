# Веб-плеер

## Библиотека

- Состав библиотеки фиксируется при запуске. Чтобы увидеть новые или удалённые файлы,
  перезапустите сервер.
- Для трека доступны имя файла, путь музыкальной директории относительно `INDEX_DIR`,
  описание и теги из индекса, а также числа файлов по категориям.

## Очередь и управление

- Плеер рассчитан на одного пользователя. Текущий трек и очередь общие для всех
  подключённых устройств и хранятся в памяти процесса сервера.
- Пропуск директории исключает оставшиеся в ней треки из будущего автовоспроизведения,
  но они остаются в плейлисте. Кнопка предыдущего трека возвращает к треку,
  который звучал до пропуска.
- Перемешивание меняет порядок только будущих треков; текущий трек и история
  сохраняются. После перемешивания переходы по директориям недоступны до перезапуска
  сервера.
- Плейлист содержит прослушанные, текущий и будущие треки. Выбор строки запускает
  её воспроизведение. Ручной выбор не меняет позицию прокрутки; к текущей песне
  список прокручивается при запуске страницы и при переходе кнопками панели плеера.
- Позиция воспроизведения хранится отдельно в каждом браузере и восстанавливается
  после обновления страницы, если сервер всё ещё показывает тот же трек. После
  обновления страницы звук не запускается автоматически.
- Если аудиофайл удалён или браузер не поддерживает его формат, плеер пытается
  перейти к следующему треку. Перемотка работает через HTTP Range без конвертации.

## Запуск

- `make local_webplayer` запускает плеер на `0.0.0.0:8090`.
- `make webplayer` запускает его на автоматически определённом IP компьютера,
  чтобы подключиться к нему с телефона в той же Wi-Fi сети.
- Для произвольных параметров используйте `src/scripts/run_web_player.py`:

  ```bash
  PYTHONPATH=src uv run src/scripts/run_web_player.py --host 127.0.0.1 --port 8091 --index-dir /путь/к/INDEX
  ```

## Для разработки

- Реализация находится в `src/web_player/`: FastAPI, шаблон Jinja2 и Vanilla JS.
  Статика — в `src/web_player/static/`.
- Основные маршруты: `GET /api/state`, `GET /api/playlist`, `GET /audio/{track_id}`;
  `POST /api/next`, `/api/previous`, `/api/next-directory`, `/api/previous-directory`,
  `/api/shuffle`, `/api/select/{track_id}` и `/api/reveal/{track_id}`.
- Очередь существует в памяти одного процесса; запуск нескольких процессов сервера
  не обеспечивает общую очередь между ними.
