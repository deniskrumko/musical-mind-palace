# Файлы INDEX.md

Каждая музыкальная директория содержит файл-индекс `INDEX.md`. Он используется
для поиска файлов, хранения тегов, текстов песен и другой информации.

Управление индексами находится в модуле `src/index/`. Единый список допустимых
тегов хранится в `config/tags.toml` и загружается не более одного раза за время
работы процесса.

## Музыкальная директория

Музыкальная директория — это папка с файлом `INDEX.md` и файлами любых форматов:

```text
INDEX.md
folders/
file.m4a
```

## Конфигурация тегов

Каждый тег описывается в секции `[tag.<key>]`. Ключ секции — внутренний ключ
тега в `Index.tags` и аргумент `Index.set`. Поле `name` — точный заголовок тега
в `INDEX.md`. Опциональное поле `display_name` хранит имя для интерфейса; если
оно не задано, используется значение `name`.

```toml
[tag.original_folder]
name = "Original folder"
display_name = "Директория"
type = "string"

[tag.other_names]
name = "Other names"
type = "list"

[tag.rating]
name = "Rating"
type = "star_rating"
```

Допустимые типы:

- `string` — непустая строка в одну строку;
- `text` — непустой текст, в том числе многострочный;
- `list` — непустой список строк;
- `single_choice` — одно значение из `choices`;
- `multi_choice` — список значений из `choices`;
- `star_rating` — целое число от 1 до 10, где 1 — очень плохо, а 10 — идеально.

Для `single_choice` и `multi_choice` поле `choices` обязательно и должно содержать
непустой список уникальных строк. Для остальных типов `choices` указывать нельзя.
Имена `name` должны быть уникальными: по ним парсер находит ключ конфигурации,
когда читает заголовок из `INDEX.md`.

Неизвестные имена и ключи, несовпадающие типы, пустые значения и значения,
которые не входят в `choices`, приводят к ошибке. Проверка применяется при
создании любого объекта `Tag`, в том числе при разборе и обновлении индекса.

## Формат INDEX.md

Каждый тег начинается с заголовка `## <name>` в начале строки. Имя должно
совпадать с полем `name` из конфига. Текст до первого тега остаётся свободным
описанием индекса.

```markdown
# Песня
Описание и ссылки.

## Original folder
Acoustic/Bad/The Wait

## Other names
- The Wait
- Ожидание
```

Для `list` и `multi_choice` каждый элемент записывается отдельной строкой,
начинающейся с `- `. Пустые строки между элементами игнорируются. Любая непустая
строка списка без маркера `- ` считается ошибкой, как и пустой элемент.

Значения всех типов должны быть непустыми. У `string`, `single_choice` и
`star_rating` значение занимает одну строку. `star_rating` хранится в Python как
`int`. `text` сохраняет внутренние и начальные пустые строки; пустые строки в
конце значения удаляются при чтении.

Строка `### ...` не является тегом и сохраняется как часть значения предыдущего
тега. Тегом считается только заголовок, начинающийся ровно с `##`.

## API модуля

Модуль `index` экспортирует Pydantic-модели `Index` и `Tag`, а также константу
`INDEX_FILENAME = "INDEX.md"`.

```python
from pathlib import Path

from index import Index

path = Path("/music/Hello/INDEX.md")
index = Index.load(path)
index.set("original_folder", "Acoustic/Bad/The Wait")
index.set("other_names", ["The Wait", "Ожидание"])
index.save(path)
```

- `Index.load(path)` читает UTF-8; если файла нет, возвращает пустой индекс.
- `Index.parse(text)` разбирает Markdown, а `render()` собирает его обратно.
- `Index.set(key, value)` ищет тег по ключу секции в конфиге, проверяет значение
  и заменяет прежний тег с тем же ключом.
- `Index.tags` — словарь объектов `Tag`, индексированный ключами секций TOML;
  объект `Tag` хранит Markdown-имя, тип и значение.
- При чтении повторяющихся заголовков сохраняется последнее значение.
- `merge(incoming)` соединяет свободные описания и заменяет совпадающие теги
  входящими значениями.
- `save(path)` записывает UTF-8; родительская папка должна существовать.

Символические ссылки вместо файла индекса отклоняются при чтении и записи.
Промежутки между тегами нормализуются, свободное описание до первого тега
сохраняется.
